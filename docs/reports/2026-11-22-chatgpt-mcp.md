# Аудит и проверка интеграции IPOS.Plan с ChatGPT через MCP

22 ноября 2026. Репозиторий [Human-Unit/IPOS.Plan](https://github.com/Human-Unit/IPOS.Plan), ветка `feat/ai-workspace-mcp-foundation`, [PR #34](https://github.com/Human-Unit/IPOS.Plan/pull/34), [issue #33](https://github.com/Human-Unit/IPOS.Plan/issues/33). Проверенная исходная точка локальной копии — `c724d59` поверх `main` на `8ad8811`. Анонимный Git-запрос к PR потребовал входа, поэтому актуальность закрытого PR на момент аудита не подтверждена.

Прочитаны `AGENTS.md`, `PRODUCT.md`, `ARCHITECTURE.md`, `PLAN_SCHEMA.md`, `CHATGPT_MCP.md` и дизайн-плейбук. Проверены написанные в ветке маршруты, Blob-адаптер, модель portable JSON, авторизация и два браузерных диалога. Исходная ветка уже содержала ручной JSON-RPC, админский API, CRUD и предварительные просмотры. Реальный OAuth, подключение ChatGPT и изоляция нескольких владельцев отсутствовали.

## Риски и изменения

| Приоритет | Наблюдение | Результат |
| --- | --- | --- |
| P0 | Подтверждённого обхода авторизации или автоматической выгрузки локальных планов в проверенном коде не выявлено. | Это проверка исходного кода и локальных сценариев. Развёрнутый сервер не проверялся. |
| P1 | Приватные черновики использовали переменную публичного Blob store. Режим хранилища задаётся при его создании. | Для всех операций AI workspace выделена отдельная серверная переменная приватного store. |
| P1 | Старые маршруты читали тело целиком до проверки длины и могли вернуть текст исключения провайдера. | Телам заданы лимиты при чтении. Схемы строго проверяют поля и версии. Ошибки провайдера возвращаются как нейтральный 503. |
| P1 | Один bearer-ключ давал все права. Полная замена полагалась на описание инструмента. | Сервер разделяет чтение и запись. Полная замена требует явного параметра и разрешения владельца. OAuth и доступ нескольких владельцев остаются отдельной задачей. |
| P1 | Повтор создания плана мог создать копию. Конкурирующее добавление задачи могло вернуть конфликт уже выполненному повтору, а замена могла удалить маркер повтора. | Одновременные запросы используют CAS. Ключ создания возвращает тот же документ. Маркеры добавления хранятся в закрытой записи отдельно от portable JSON. |
| P1 | Применение облачной копии не было связано с версией локального предпросмотра. Запись привязки была отдельной от изменения документа. | Проверяется локальная версия и серверная версия. План, предыдущая ревизия, событие и привязка фиксируются в одной транзакции IndexedDB. |
| P2 | Структура входов MCP дублировалась вручную и могла расходиться с фактической валидацией. | Официальный SDK строит описание из Zod и выполняет разбор протокола. Сохранены шесть инструментов. |
| P2 | На мобильных видимая надпись GPT может быть скрыта. При ошибке списка диалог предлагал войти даже при недоступном хранилище. | Кнопка GPT имеет постоянное доступное имя. Предложение входа показывается при 401. |

Облачные операции проверены моками. Сценарий двух Reels использует и сохраняет поля ответственных «Ислом» и «Гулнамо, Шехрона», описания и две ссылки без дедлайнов. Повтор с тем же ключом не создаёт вторую запись. Совпадение текста само по себе ключом повторной операции не является.

## Проверки

| Проверка | Результат |
| --- | --- |
| `npm ci --offline --no-audit --no-fund` | PASS, 548 пакетов из локального кэша. |
| `npm run lint` и `npm run typecheck` | PASS. |
| `npm test` | PASS, 112 тестов из 17 файлов. |
| `npm run build` | PASS со второй попытки. Первую остановило уведомление Next.js 16.4.1 об известной уязвимости. |
| Новый Playwright `ai-sync.spec.ts` | PASS, два сценария на локальной production-сборке с моками API. |
| Полный Playwright, блокировка внешнего DNS | FAIL: 39 прошли, 6 проверок консоли зафиксировали ошибки загрузки внешних шрифтов, 2 пропущены. |
| Полный Playwright, локальная заглушка для CSS шрифтов | PASS: 45 прошли, 2 пропущены. Проверки и ожидаемые результаты сохранены. |

Unit-тесты пропускают MCP-запросы через реальный SDK с локальным мок-адаптером Blob. Они проверяют обе версии протокола, авторизацию и набор инструментов, конкурентный повтор, конфликт версии, ошибку поставщика, лимит без `Content-Length` и валидацию. Браузерные тесты проверяют подтверждение отправки одного плана, повторный просмотр после конфликта, сохранение предыдущей версии, импорт в отдельный редактируемый документ и экспорт JSON. Fake IndexedDB отдельно проверяет, что запись из другой вкладки не перезаписывается.

Две проверки входа владельца пропущены, потому что тестовые учётные данные не задавались. Второй браузерный прогон использовал игнорируемую Git копию набора, где подменялся только сетевой ответ для CSS шрифтов. Использовались системные шрифты. Реальный CDN шрифтов и внешнее хранилище не проверялись.

## Перед подключением

Требуются личная HTTPS-инфраструктура и приватное хранилище, интеграционный прогон с тестовыми данными, OAuth с проверкой issuer, audience и прав, лимиты на обращения, проверка Live ChatGPT и обновление уязвимой версии Next.js. Для многопользовательского использования нужна отдельная модель владельцев и тесты изоляции. Подробная схема и настройки приведены в [документации интеграции](../CHATGPT_MCP.md).

Локальные коммиты реализации: a4786a9 (MCP и серверные записи) и 75bbfd9 (синхронизация и тесты IndexedDB). Для обновления PR требуется подтверждённый личный доступ к закрытому репозиторию.
