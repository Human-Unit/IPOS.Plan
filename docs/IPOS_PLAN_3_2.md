# IPOS.Plan 3.2 — Навигация по заданиям и сохранённые имена

## Основание

Ветка `feat/ipos-3-2-assignments-directory` продолжает 3.1 (`feat/ipos-plan-3-1-productivity`).
Нельзя сливать её в production до выхода PR #13 и #14.

## Реализовано

- **Назначения** в левой панели: все реальные task-блоки в исходном порядке, назначенные люди, статус и нажатие для перехода к задаче. Список не удаляет/фильтрует документ.
- **Быстрое перемещение**: предыдущая/следующая задача и индекс текущей (например, 2 / 5) над рабочим полем; работает при скрытых панелях и на телефоне.
- **Поле ответственных** поддерживает несколько имён через запятую/точку с запятой/новую строку. При завершении ввода имена сохраняются в IndexedDB settings. Подсказки позволяют повторно назначать людей из предыдущих планов.
- **Dashboard → Имена из назначений**: локальный список, автоматически пополняемый из ранее сохранённых планов; старые планы не перезаписываются. Имена сохраняются независимо от статуса задачи или удаления из текущего поручения.
- **Полный backup 3.1** теперь включает имена: allowlist валидирует entries и ограничивает количество, безопасное восстановление не создаёт повторов по нормализованному имени.
- SchemaVersion portable plan 1 и Dexie 1 без изменений. Поле `Task.assignee` остаётся строкой для обратной совместимости.

## Границы

- Имена — **кандидаты для будущего списка активистов**, не подтверждённое членство. Строки «редактор» или «команда» могут быть внесены как есть; понадобятся последующая проверка и управление профилями.
- Сопоставление происходит по имени (Unicode NFKC, регистр, ё/е). Люди с одинаковым именем пока не различаются; изменение написания не переименовывает старые задания.
- В имени одного человека допустимы пробелы; несколько людей разделяйте запятой/точкой с запятой. Встроенные URL-share snapshots не содержат локального справочника, но сами строки ответственных остаются в заданиях.
- Справочник живёт в текущем браузере и переносится только с полной резервной копией. Это не облачный аккаунт, HR-система и не синхронизация команды.
- Сохранение имён запускается по выходу из поля или выбору подсказки — **не по каждому символу**, чтобы не создавать ложные «Ис», «Исл» при наборе.
- Ошибка сохранения справочника не мешает сохранению задания в плане; UI показывает ошибку.

## Приёмка

- Назначить «Ислом, Маруф» на задачу и убедиться, что оба имени есть в справочнике.
- В другом плане выбрать их через подсказки.
- Перейти на другую задачу через строку в «Назначениях» и через стрелки, проверить выделение и скролл.
- Открыть/закрыть левую панель, проверить 1440/1024/390/320 px.
- Создать полную резервную копию → восстановить её копией и без дублирования имён.
- Проверить автосохранение, импорт старых планов, DOCX, историю, предпросмотр, совместное хранение в IndexedDB и отсутствие обновлений portable schema.

## Дальше

При отдельном согласовании: полноценная локальная «База активистов» с подтверждением профиля, псевдонимами и историей выполненных задач; потребуется отдельная модель лиц/идентификаторов и миграция, без автоматической интерпретации совпадающих имён.
